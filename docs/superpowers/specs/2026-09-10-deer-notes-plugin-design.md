# 小鹿笔记 Obsidian 插件设计

## 目标

建立一个可提交到 Obsidian Community Plugins 的桌面端插件，为任意 Vault 提供知识看板、快速笔记、Markdown 阅读和原文摘录能力。第一版以桌面端为验收目标，代码不依赖 Node.js 文件系统接口，为后续移动端兼容保留基础。

## 产品边界

第一版包含：

- 一个可由侧边栏图标和命令面板打开的“小鹿笔记”自定义视图。
- 固定的“全部笔记”入口，以及根据 Vault 一级目录动态生成的导航。
- 最近 13 周贡献热图、笔记列表、目录内容列表和 Markdown 阅读。
- 快速创建 Markdown 笔记，支持标签、粗体、有序列表、无序列表和图片附件。
- 阅读原文时选中文本，显示单一“做笔记”浮层；保存原文引用、个人笔记和来源链接。
- 可配置笔记目录、附件子目录和隐藏的一级目录。
- Vault 文件变化后的增量刷新。

第一版不包含 AI、账号、云同步、遥测、自动整理、删除或迁移用户文件，也不接管 Obsidian 全局右键菜单。

## 技术路线

使用 Obsidian 官方 TypeScript API 构建原生插件。界面使用 `ItemView` 和 Obsidian CSS 变量；文件读取、写入和监听使用 `Vault`、`MetadataCache` 与 Workspace API。现有 HTML 看板只作为视觉与交互参考，不复用浏览器目录选择、IndexedDB 或 File System Access API。

工程使用 TypeScript、esbuild、Vitest 和 jsdom。发布产物为 `main.js`、`manifest.json` 和 `styles.css`。

领域函数保持无 Obsidian 依赖，便于单元测试。Obsidian API 只出现在服务、视图和插件入口层。

## 设置与首次使用

默认设置：

- `notesFolder`: `小鹿笔记`
- `attachmentsFolder`: `附件`
- `hiddenRootFolders`: `[]`

插件启用时只注册能力，不立即修改 Vault。用户第一次保存笔记或图片时才创建笔记目录及附件目录。若 Vault 已存在 `80 笔记`，插件不自动切换或迁移；用户可在设置中主动选择它。

设置页使用 Obsidian 的文件夹建议输入，保存前校验路径必须是 Vault 内的相对路径，拒绝空路径、`.`、`..` 和笔记目录自身的附件循环配置。

## 导航与内容

“全部笔记”固定为第一项，只显示 `notesFolder` 下由插件识别的笔记。其余菜单来自 Vault 根目录的直接子目录，按名称自然排序，并排除：

- 当前笔记目录。
- 以 `.` 开头的隐藏目录。
- 用户在设置中隐藏的目录。

一级目录创建、重命名和删除后，导航在当前视图中增量更新。目录菜单显示该目录中的 Markdown 内容，子目录内容包含在内。知识概览放在动态目录之后，作为最后一个固定入口。

插件不在每个一级目录内创建笔记子目录；整个 Vault 只使用设置中指定的一个笔记目录。

## 笔记数据格式

插件笔记是普通 Markdown，以 frontmatter 标识：

```markdown
---
type: deer-note
created: "2026-09-10"
updated: "2026-09-10"
source: "01 收件箱/原文.md"
tags: [思考]
---

# 第一段笔记文字

来源：[[01 收件箱/原文]]

## 12:14:39

> 被选中的原文

第一段笔记文字。
```

独立笔记的 `source` 是空字符串，不生成来源行。插件只把 `type: deer-note` 视为自己的笔记，避免把用户在笔记目录中的其他 Markdown 错纳入“全部笔记”。

新文件的标题和文件名取第一次笔记内容的第一个非空段落，移除 Markdown 标记和 Windows 非法文件名字符，最长 60 个字符；为空时使用“未命名笔记”。重名依次追加 ` (2)`、` (3)`。创建后文件名稳定，不因后续追加而改变。

同一来源、同一自然日的摘录追加到同一篇插件笔记。匹配依据是 frontmatter 的 `source` 与 `created`，不依赖文件名。追加前使用最新文件内容，避免覆盖其他编辑；发生冲突时保留编辑器草稿并提示重试。

## 快速笔记与附件

看板顶部提供紧凑的 Markdown 输入框，不单独要求标题。保存独立笔记时使用第一段命名。工具栏第一版支持标签、图片、粗体、无序列表、有序列表和预览。

图片写入 `<notesFolder>/<attachmentsFolder>/`，文件名使用随机 UUID 和经过 MIME 类型校验的扩展名。Markdown 使用相对链接。允许 PNG、JPEG、GIF 和 WebP，单张最大 20 MB。写入失败时不清空文字草稿。

## 阅读与选文摘录

点击 Markdown 文档后在插件视图内进入全屏阅读状态，左侧提供关闭按钮，并提供“在 Obsidian 中打开”。阅读内容使用 Obsidian MarkdownRenderer，保持内部链接和主题兼容。

用户用鼠标或键盘选择阅读正文内的非空文本后，在选区下方显示一个只包含“做笔记”的插件浮层。插件仅阻止阅读区域内由该浮层替代的 `contextmenu`，不修改 Obsidian 其他区域或其他插件的菜单。

点击“做笔记”打开摘录编辑器：上方只读展示原文，下方输入 Markdown 笔记。保存成功后刷新关联笔记；失败时保留选文和输入。Escape 可以关闭浮层或编辑器，焦点返回原选区附近。

移动端没有右键和精确鼠标选区，因此后续兼容采用原生文本选择后的命令入口；第一版不把该交互列为移动端验收项。

## 贡献热图

热图固定展示最近 13 周的 91 个日期格，无数据时仍显示空格和零统计。第一版统计插件笔记文件的创建/修改日期，标题明确为“最近修改活动”，不声称是完整历史。

若后续需要准确的历史贡献，另行设计本地活动记录；第一版不在 Vault 内写入隐藏统计文件。

## 索引与性能

首次打开视图时从 `Vault.getMarkdownFiles()` 建立轻量索引，读取插件笔记内容和必要的 metadata。之后监听 Vault 的 `create`、`modify`、`delete` 和 `rename` 事件，只更新受影响条目。

插件加载阶段不读取全部文件内容，不在 `onload` 中进行完整扫描。视图关闭时释放 DOM 监听器和订阅，插件卸载时注销所有资源。

## 错误处理和安全

- 所有写入通过 Vault API，限制在配置的笔记目录及附件子目录。
- 不读取或修改 `.obsidian`。
- 不删除、不移动、不批量重命名用户文件。
- 保存失败显示 Obsidian Notice 和输入框附近错误，草稿保留。
- 路径冲突、目录与文件同名、来源已删除均给出可理解提示。
- 外部链接使用 Obsidian 标准处理方式，不注入不受信任 HTML。
- 插件无网络请求、遥测、动态代码和广告。

## 主题、可访问性与移动端预留

颜色、字体、边框和背景使用 Obsidian CSS 变量，兼容明暗主题。图标使用 Obsidian `setIcon` 提供的 Lucide 图标。按钮包含可访问名称，键盘可遍历；焦点样式保留，正文输入框只显示文字光标。动效遵循 `prefers-reduced-motion`。

不使用 Node `fs`、绝对路径、浏览器 File System Access API 或桌面专属 Electron API。响应式 CSS 保证窄屏不横向溢出，为后续移动端调试保留条件。

## 测试与验收

自动测试至少覆盖：

- 一级目录过滤、排序及新增目录后的导航结果。
- 默认目录和自定义目录路径校验。
- 第一段标题提取、非法字符、空标题和重名序号。
- 独立笔记创建以及同来源同日追加。
- 不同来源或不同日期不错误合并。
- 引用、来源链接、标签和 frontmatter 输出。
- 91 格贡献数据和空数据状态。
- 保存冲突与失败时草稿不丢失。

桌面端手工验收：

1. 在空白 Vault 安装后，打开看板不创建文件。
2. 首次保存创建 `小鹿笔记`，笔记能被 Obsidian 正常打开。
3. 切换至已有 `80 笔记` 后不迁移旧文件。
4. 新增、重命名、删除一级目录，导航无需重启插件即可更新。
5. 阅读任意 Markdown，选文后只出现插件的“做笔记”浮层。
6. 保存摘录后可看到引用、个人笔记和来源链接，原文未改变。
7. 默认主题和一个常见第三方明暗主题下布局可读。

## 发布准备

仓库包含 README、LICENSE、版本发布脚本和 GitHub Actions。首个公开 Release 附带 `main.js`、`manifest.json`、`styles.css`，版本号与 manifest 一致。提交社区目录前执行自动测试、构建、类型检查、官方插件审查清单和干净 Vault 手工验收。
