# Deer Notes：从记录到认知的迭代路线

## 1. 文档信息
2026-09-12。状态：产品方向草案，第一阶段已有本地实现。版本号表示规划顺序，不表示已经发布，也不构成排期承诺。负责人：用户负责真实场景验收，Codex 负责方案、实现和自检。

## 2. 目标和问题
用户明确要求围绕知识积累、学习和转化为自身认知持续迭代，并保持简洁、整齐、流畅、中英文可用。当前已具备记录、阅读、摘录、搜索和概览；尚未形成回忆、应用、修正的闭环。

核心假设：价值不应只用笔记数量衡量，而应看用户能否脱离原文解释观点、找到适用场景、辨识反例，并保留实践后改变理解的依据。这个假设需要实际使用反馈验证，不能用文件数或热力图推断掌握程度。

目标用户是使用本地 Obsidian 知识库的个人。优先解决读完即忘、摘录与理解混杂、找不到旧知识、没有应用记录的问题；不引入账户、云端上传、付费服务或自动改写整库。

## 3. 版本路线

| 阶段 | 要解决的问题 | 最小可验收能力 | 成功信号 |
| --- | --- | --- | --- |
| 基础修复 0.1.x | 原有知识库无法有效浏览 | 主题层次、导航对齐、常显活动、已有 Markdown 搜索 | 能从真实库找到原文 |
| 0.2 理解 | 收集原句后没有自己的表达 | 摘录中的可选“我的理解 / 已有联系 / 尝试应用”提示 | 用户能写出原文之外的解释或问题 |
| 0.3 回忆 | 看过不等于能回忆 | 用户主动加入回顾；先看问题、尝试作答，再展开原文；可跳过、移除 | 能暴露模糊点并修订理解 |
| 0.4 连接 | 新旧知识彼此隔离 | 展示明确来源与反向链接；用户说明“支持 / 反例 / 应用”关系 | 关系有理由，而非只有连线 |
| 0.5 应用 | 概念停留在笔记里 | 以真实问题组织相关笔记，记录一次尝试、结果和局限 | 能回溯一次知识应用过程 |
| 0.6 修正 | 不知道自己为什么改变看法 | 保留旧观点、新观点、改变依据；按问题回顾实践记录 | 用户能说明认知变化的证据 |

顺序可由反馈调整。发现前一阶段无效就先修正，不为凑版本数量继续增加功能。标签组合筛选、收件箱整理作为检索能力按需补齐，不抢占学习闭环的优先级。

## 4. 当前阶段需求与流程

- FR-001（P0）：用户选取原文并打开摘录窗口后，可直接自由记录，也可点击任意思考提示。
- FR-002（P0）：点击提示只追加对应 Markdown 小标题，并显示一个具体问题；不生成用户的理解、不替换现有草稿。同语言同标题重复点击不重复插入。
- FR-003（P0）：思考提示覆盖自己的解释、与笔记或经历的联系及反例、具体应用问题与观察方法。
- FR-004（P0）：保存使用现有摘录服务，原文与用户笔记保持区分；保存失败保留原文与草稿，允许重试，保存期间禁用提示。
- FR-005（P0）：中英文界面均可用，键盘焦点停留在弹窗内；切换界面语言不翻译已输入内容。

主流程：阅读 → 选文 → 做笔记 → 自由输入或选择提示 → 写自己的内容 → 保存 → 在正常 Markdown 笔记里阅读。
分支：可不使用提示；取消不写入；重复点击不丢草稿；失败显示原因并保留内容。空标题不是理解证明，不统计为掌握。

## 5. 数据、兼容与边界
第一阶段不增加数据库或迁移，用现有 Markdown 正文与来源字段保存。用户可在 Obsidian 原生编辑，插件停用后内容仍可阅读。只处理用户主动打开的摘录，不扫描内容来自动打分，不上传知识库，不新增遥测。

后续回顾阶段须先设计可迁移的笔记标识、重命名与删除处理、回顾记录和重复提交保护，再开发。间隔参数应可调整，回顾队列有上限，可暂停；不制造未完成任务堆积。初始最多 3 条是待验证的产品假设，不是科学最优值。

连接阶段优先使用 Obsidian 原生链接与元数据能力。明确区分真实链接与算法推荐；推荐必须说明理由，用户决定是否建立关系。应用阶段先做简单实践记录，不扩成项目管理系统。

## 6. 验收与证据
第一阶段：原有草稿不被覆盖；重复提示无重复标题；正文和来源准确保存；失败恢复；保存期间提示不可点击；中英切换不改笔记；窄屏弹窗可滚动；无额外网络请求。

每轮完成：一个核心场景、相应异常回归、插件及预览构建、可查看的预览、变更与局限记录。浏览器通过不等于真实 Obsidian 主题、移动端及大型库已通过。未测项目必须明示。

效果先通过用户自愿提供的场景反馈判断：这条记录是否有自己的解释？回顾时能否回答？有没有在实际问题中使用？不采集私人内容来计算“认知分数”。

## 7. 持续迭代规则
每轮读取此文档、工作区差异和已有验收记录，选一个最小切片；提出使用假设 → 实现 → 自检 → 预览 → 记录结果。只自检可确认功能行为，不能宣称已经验证学习效果。已有数据保持兼容，不自动批量移动、改写或删除真实笔记。

有用户反馈时优先修复；没有反馈时可推进明确的实现和验证，影响认知流程的新假设先以预览交付。计划完成后再评估下一阶段，不无限增添菜单。已创建每日 10:00 的当前任务自动迭代（deer-notes），暂按本地预览交付；用户可随后调整频率和正式发布策略。自动任务依赖宿主可执行环境，文档本身不会自动执行。

回滚：第一阶段停用新版即可恢复旧界面，已保存的 Markdown 不需要迁移。后续任何数据结构改变必须附兼容与回滚方案。
